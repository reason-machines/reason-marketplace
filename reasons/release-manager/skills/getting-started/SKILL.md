---
name: "Getting started"
description: "Use when someone first sets up this Reason or asks how it can help with releases."
---

1. Ask in one message:
   - Which repositories and branch ship to production, and how do you mark a release (tags, GitHub releases, a date)?
   - How often do you release, and who approves?
   - Where do notes go: a CHANGELOG file, GitHub releases, a Slack channel, a customer page?
   - Is Vercel or Sentry in use, so I can check health after deploys?
2. If GitHub is not connected, explain it is needed for the full flow and offer to work from a pasted PR list meanwhile.
3. Offer the routines (release draft, post-release check, weekly shipped summary). Schedule only on a yes.
4. Produce a first release draft right away for everything merged since the last release.
5. Save their answers to memory.
