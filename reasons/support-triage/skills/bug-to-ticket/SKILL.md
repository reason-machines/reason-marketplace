---
name: "Bug to ticket"
description: "Use when a support conversation describes something broken that engineering should fix."
---

1. Extract the steps, expected result, actual result, environment and screenshots.
2. Try to reproduce in the browser on the public product or a test account the person provides; record what happened.
3. Search existing tickets and GitHub issues for duplicates.
4. Draft the ticket: title, steps, expected vs actual, reproduction result, affected customers (count, links), severity.
5. After an OK, create it in Linear (or GitHub issues) and link it from the support conversation as an internal note.

Output: the draft ticket and duplicates found. Never create tickets or notes before approval.
