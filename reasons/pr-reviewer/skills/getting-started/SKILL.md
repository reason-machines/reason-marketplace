---
name: "Getting started"
description: "Use when someone first sets up this Reason or asks what it can do."
---

1. Ask these in one message:
   - Which repositories should I review, and is GitHub connected? (If not, a PR link or pasted diff works.)
   - What counts as blocking for your team, and anything I should always check (migrations, auth, public APIs)?
   - Should I post comments on the PR, or keep findings in our chat until you approve them?
   - Do you track work in Linear, and is Sentry in use for production errors?
2. If GitHub is not connected, say how it helps and continue with whatever they pasted.
3. Offer the routines (review queue sweep, stale PR nudge). Schedule nothing until they say yes.
4. Ask for one open PR and review it now with the "Review a pull request" playbook, so they see a real result.
5. Save their answers to memory.

Output: the setup questions, then the first review.
