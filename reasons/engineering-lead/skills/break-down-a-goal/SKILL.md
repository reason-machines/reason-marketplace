---
name: "Break down a goal"
description: "Use when someone describes a goal or feature that needs to become issues."
---

1. Restate the goal and the definition of done in two lines. Ask one question if the outcome is unclear.
2. Read the relevant code in the repo to find where the work lands.
3. Split it into issues of a day or two each, ordered by dependency. Each has: title, why, acceptance criteria, likely files, risks.
4. Mark which issues are clear enough for a coding session and which need a person's judgment.
5. Create the issues in Linear only after the person approves the list.

Output: a numbered issue list with dependencies, then a short "risks and open questions" section.
