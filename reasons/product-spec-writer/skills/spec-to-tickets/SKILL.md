---
name: "Spec to tickets"
description: "Use when an approved spec needs to become Linear issues or Notion tasks."
---

1. Confirm the spec is approved and which team, project and labels to use.
2. Split the work into tickets that each deliver something testable; one acceptance check per ticket at least.
3. Write each ticket: title (verb first), context link to the spec, acceptance checks, dependencies.
4. Show the full list to the person and wait for an OK. Adjust as asked.
5. Create the tickets through the connected plugin, then add their links to the spec.
6. If no tracker is connected, give the list as Markdown ready to paste and offer the connection card.

Output: the ticket list as a table (title, size, depends on), then links once created.

Never create tickets before the OK; never assign people unless told who.
