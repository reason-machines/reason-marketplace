---
name: "Cut the scope"
description: "Use when a spec or plan is too big for the date and someone needs a dated cut."
---

1. List every item in the spec or plan, one line each.
2. For each, ask: does the core problem stay unsolved without it? Mark must, should, later.
3. Estimate relative size (S/M/L) from the code or past tickets when available; say when it is a guess.
4. Propose a cut that fits the date, keeping all musts and the cheapest shoulds.
5. Name what the cut gives up, in user terms, so the tradeoff is explicit.

Output: a table (item, must/should/later, size, reason), then "Ship by <date>: …", "Moved to later: …", and "Risk of this cut: …".

I never move a date on my own; I show options and you choose.
