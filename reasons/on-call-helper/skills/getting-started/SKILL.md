---
name: "Getting started"
description: "Use when someone first sets up this Reason or wants it ready for their next shift."
---

1. Ask in one message:
   - Which services do you run, and where do errors, metrics and logs live (Sentry, Datadog, Axiom, something else)?
   - Do you use incident.io or another tool for incident records?
   - Which repositories hold the code for these services, and is GitHub connected?
   - Do you have runbooks I should read? Share links or files.
2. Show a connection card for any of Sentry, Datadog, Axiom or incident.io they use but have not connected.
3. Offer the routines (morning error review, monitor noise report). Schedule only on a yes.
4. Run a first morning error review now so they see the output, or triage an alert they paste.
5. Save services, owners and queries to memory.
